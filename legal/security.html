SeedCode CLI: Security
information.

Last updated: 5 November 2026. How SeedCode CLI handles credentials, permissions and reports.

1. Design model

SeedCode CLI runs on your machine, acts inside the workspace you choose, and talks only to the provider you configure. There is no SeedCode account server, no hosted relay and no telemetry.

2. Credential storage

  • API keys are stored in ~/.seedcode/config.json with restricted file permissions where the OS supports it.
  • Keys can instead come from environment variables or a project .env; environment values are never written into another provider's slot.
  • Keys are masked in the interface and must never appear in logs, error messages or URLs.
  • Provider credentials stay on your machine; requests go directly to that provider over TLS.

3. Permission model

The default mode asks before risky actions such as running a shell command, deleting a file, changing git state or writing outside the workspace. Read-only operations follow the configured level. An explicit Allow-All mode can auto-approve supported actions for the session after you confirm a warning; it never bypasses operating-system security, a sandbox or a provider's own limits. See the terms and the project README for the full policy.

4. AI-generated code is untrusted

Model output can contain insecure or destructive instructions. Review diffs, keep backups, and do not run generated commands you do not understand. Never expose secrets to a model or to a provider you do not trust.

5. Supported versions

Security fixes are applied to the latest published release. Older versions are not guaranteed to receive patches. Check releases for the current version.

6. Reporting a vulnerability

Please report suspected vulnerabilities privately first. Use GitHub's private vulnerability reporting on the repository security page, or email github@eagox.studio. Include the version, operating system and reproduction steps. Do not open a public issue for an unpatched vulnerability, and do not test against systems you do not own. No response time or bounty is promised; reports are reviewed on a best-effort basis.

7. Third-party scope

Security of GitHub, OpenRouter, Ollama, AeroLink, FreeModel and custom endpoints is that provider's responsibility. Report issues in those services to them directly. SeedCode cannot review, patch or guarantee third-party infrastructure.

8. No guarantees

SeedCode CLI is provided without warranty. This page describes the current implementation, not a certification, audit or compliance guarantee.
